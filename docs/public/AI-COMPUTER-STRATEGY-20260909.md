# H3 AI Computer — 앱 조사와 단계별 제품 전략

확인일: **2026-09-09 (KST)**. 목표는 사용자가 말로 지시하면 내 컴퓨터의 모델·자료·앱을 함께 사용하는 작업 환경이다. 로컬 브레인이 기본이며 온라인 브레인은 사용자가 선택한다.

## 조사 범위와 판단

모든 앱을 빠짐없이 조사했다거나 세계 인기 순위를 확정한 자료가 아니다. 범용 에이전트, 로컬 모델, 지식 관리, 코딩, OS 제어, 미디어, 워크플로 분야의 대표 제품·도구 14개를 공식 문서로 비교했다. 웹 문서의 기능 확인과 직접 실행 검증을 구분한다. 요금제·OS·버전에 따른 차이가 있으므로 계약 전 다시 확인한다.

인기도의 수치 근거는 서로 비교 가능한 활성 사용자 통계가 드물다. 예를 들어 Ollama는 2026-07-09에 개발자 890만 명을 발표했지만 이는 **회사 자체 발표**이며 다른 앱의 MAU와 순위 비교하지 않는다. [Ollama 발표](https://ollama.com/blog/all-aboard-open-models)

## H3의 차별화 방향

**“내 컴퓨터가 이해하고, 만들고, 실행한다.”** 모델 선택 화면에서 끝나지 않고 업무 결과까지 연결한다. 소프트웨어는 설치된 장비의 메모리·모델 준비 상태와 실제 작업 성공률을 함께 보여준다.

- **Brain:** 로컬 모델 기본. Codex·Claude·API 브레인은 명시적 선택. 서비스 전환으로 과거 자료를 자동 재전송하지 않는다.
- **Context:** 선택한 프로젝트와 앱만 읽는다. 로컬 검색에 출처·삭제·보존 기간을 제공한다.
- **Tools:** 파일·미디어 → 브라우저/API → OS 접근성 → 필요한 경우 영상 기반 GUI 순으로 확장한다.
- **Control:** 무엇을 어느 앱에서 실행하는지 보여주고 중단할 수 있게 한다. 모든 버튼 누름을 되돌릴 수 있다는 약속은 하지 않는다.
- **Evidence:** 에이전트의 “완료” 메시지보다 실제 파일·UI 상태·미디어 결과를 기준으로 성공을 판정한다.

사용 예: “회의 자료에서 30초 소개안을 만들고, 로컬 이미지·음성 작업을 준비하고, 편집 앱에 제목을 입력해줘.” 각 결과물은 하나의 프로젝트에 모이고, 외부 서비스 사용과 최종 제출은 보이는 선택이 된다.

## 구현 순서와 출고 기준

| 단계 | 범위 | 통과 기준 / 현재 상태 |
|---|---|---|
| 1. 실행 가능한 Mac 제어 | 앱 선택, 접근성 관찰·활성화·버튼·텍스트, 요청별 승인, 중단, 한·영 UI | 이번 구현. 정책/브로커 테스트와 별도 테스트 앱의 실제 AX 조작 통과. 일반 앱·실모델 업무 성공률은 미측정 |
| 2. 브라우저·프로젝트 | 고정 버전 Playwright 연결, 격리 프로필, 프로젝트 파일 검색·미디어 큐, 작업별 템플릿 | 공개/오프라인 테스트 사이트 20개 과제. 다른 프로필·권한 외 파일 접근 0건, 제출 전 승인 누락 0건 |
| 3. 장기 작업 브레인 | Codex App Server / Claude 어댑터, 로컬 구조화 도구 호출, 재개·체크포인트·진행 중 수정 | 동일 20개 과제로 모델별 성공률·시간·토큰/비용·개입 수 비교. 중단·앱 재시작 후 중복 실행 0건 |
| 4. 쉬운 설치·음성 | 기기별 모델 추천, 용량·라이선스·업데이트 이력, 다운로드 재개, push-to-talk | 깨끗한 설치 환경에서 모델 준비부터 첫 작업까지 검증. 외부망 차단 상태에서 준비된 로컬 업무 통과 |
| 5. Windows/Linux 제어 | Windows UI Automation, Linux AT-SPI 및 Wayland 권한 경로별 어댑터 | 각 OS 실기기에서 동일 과제 통과 전에는 해당 제어 기능을 지원 완료로 표시하지 않음 |
| 6. 연결 장치 | 장치 상태, 시뮬레이션, 명시적 동작 API | 로봇은 별도 안전 제어기·인터록·물리적 정지 사용. LLM이 서보/실시간 안전 루프를 직접 담당하지 않음 |

단계는 출시 약속 날짜가 아니라 검증 게이트다. 1단계 이후의 기능은 계획이며 현재 구현으로 홍보하지 않는다. 특히 현재 공유 Electron 앱에는 이 Mac AX 제어가 연결되지 않았다.

## 컴퓨터 제어 1단계 사용법과 경계

Mac 앱 → **AI 에이전트 → 컴퓨터 제어 · Mac 프리뷰** → 대상 앱 선택 → 필요 시 시스템 설정에서 H3의 손쉬운 사용 권한 허용 → 브레인·기록용 작업 폴더·요청 지정.

예: 테스트 문서 앱을 열고 “선택한 앱을 관찰하고 제목 입력란에 ‘신제품 소개’를 입력해줘. 저장이나 외부 전송은 하지 말아줘.”

1. 관찰도 승인 후 실행한다. 결과는 선택한 브레인과 로컬 작업 기록에 포함된다.
2. 버튼·텍스트 입력은 실제 관찰에서 받은 ID로만 요청할 수 있다. 60초, 새 관찰, 한 번의 변경, 거절 또는 중단 시 권한이 만료된다.
3. 실행 직전 같은 프로세스·요소 속성·지원 동작을 재확인한다. 앱의 모든 UI 변화나 다른 앱으로 파생되는 부작용까지 격리하는 OS 샌드박스는 아니다.
4. secure text field와 그 하위 요소를 제외한다. 일반 텍스트에 들어 있는 개인정보를 자동으로 모두 식별하는 기능은 아니다.
5. 관찰은 최대 100노드/깊이8, 텍스트 길이를 제한한다. 큰 앱 전체를 한 번에 읽거나 캔버스·게임 UI·임의 키보드/마우스 좌표를 제어하는 기능은 아직 없다.
6. 현재 브레인 루프는 최대8단계이며 모든 컴퓨터 작업을 개별 승인한다. 작업 성공률을 확보한 뒤 저위험 반복 작업의 승인 묶음을 검토한다.
7. 앱 API가 제공하는 텍스트 **대체** 기능이다. 삽입 커서 위치에 타이핑하는 것과 다르다. 실제 결과는 재관찰해야 한다.
8. 손쉬운 사용 권한은 실행 파일/앱 서명에 영향을 받는다. 테스트 바이너리 권한이 배포 앱의 권한 허용을 대신하지 않는다.

Apple 접근성 API를 사용한다. [AXUIElement](https://developer.apple.com/documentation/applicationservices/axuielement), [권한 확인](https://developer.apple.com/documentation/applicationservices/1460720-axisprocesstrusted)

## 검증 및 다음 의사결정

자동 검증: `python3 apps/macos/Tests/run_fixture.py`, `bash scripts/test-mac-app.sh`, `bash scripts/test-mac-localization.sh`.
실제 별도 테스트 앱: `bash scripts/test-mac-computer-live.sh`. 권한 없는 CI는 명시적으로 SKIP하며 실제 AX 성공으로 계산하지 않는다.

2026-09-09 로컬 확인: 별도 AppKit 테스트 앱에서 화면 관찰, 비밀번호 요소 제외, 한·영 텍스트 대체, 버튼 실행, 디스크 결과 확인 통과. 이는 **모델을 사용하지 않은 실행기 검증**이다. 브로커 승인/거절/중단은 가짜 로컬 모델 서버로 검증했다. 실모델의 계획·복합 업무 수행, 모든 앱의 호환성, 오프라인 전체 네트워크 차단 실험은 아직 결과가 없다.

다음 실험은 설치된 로컬 모델별로 텍스트 앱·브라우저·미디어 앱의 20개 과제를 동일하게 반복한다. 목표 예시는 성공률 90% 이상, 권한 밖 동작 0건이며 아직 달성 결과가 아니다. 성공한 작업당 사용자 개입 수·지연 p50/p95·생성 비용을 함께 평가한다. 모델 이름이나 도구 수만으로 “최고”를 판정하지 않는다.
